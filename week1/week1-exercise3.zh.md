## 2. 我做了哪些改动

### 2.1 输入校验（拒绝非法值与负数）
- `parse()` 改用严格正则（L50）：`0x10`、`7.8abc`、`1e` 这类前缀垃圾一律拒收，不再被静默当成 0。
- 去掉正则里的符号位 `[+-]?`（L50）：货币没有负值，金额 / 汇率 / 结果框输入负数一律拒收。
- 非法或负数输入触发红框提示（L62–63 的 `flag()`，L73–74 调用），不再"无声清空"。

### 2.2 精度隔离（货币只有两位小数）
- `show()` 在数值被舍入成 0 时退回有效数字表示（L57–59）：`1e-7` 不再显示成 `0`。
- 新增 `exactFrom` 作全精度权威源（L64–65）：点 ⇅ 交换方向时用精确值反算，避免 `1000 → 128.21 → 1000.04` 的四舍五入漂移（L67–75、L77–84、L87–94）。

## 5. 练习③ 两段解释（署名：邹佳辰 / Richard）

> 输入一定得是数字，所以我给输入框加了格式检测——`0x10`、`7.8abc` 这类非法值会被红框标出，而不是被悄悄当成 0 让结果无声出错；结果显示也只保留现实里存在的两位小数精度，因为货币根本没那么多小数位，多余的小数既不符合实际、又会在来回点 ⇅ 时把四舍五入误差越累积越大。
> 这两处都是堵"AI 说能跑 ≠ 真对"的口子：非法输入被吞掉会让人误以为算对了，而钱天然只有两位精度，扛着无意义小数既误导、又会在往返换算时漂移（练习②就抓到过 `1000→128.21→1000.04`）。
